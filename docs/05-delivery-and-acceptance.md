# 实施计划与验收标准

版本：1.1｜日期：2026-09-30｜第一版本地应用已建立，内容审核和公网发布尚未完成

## 1. 开发阶段

| 阶段 | 任务 | 退出条件 |
|---|---|---|
| M0 内容与素材准备 | 校核 78 张名称、文件映射；整理 156 段正逆位基础牌义；准备音频；生成展示图与清单 | 映射完整、牌义可审核、原图保留、下载体积满足预算 |
| M1 架构与数据 | 建立 React、FastAPI、SQLite、IndexedDB、JSON schema、版本与迁移；配置同域开发 | 数据接口和本地存储可用，契约校验通过 |
| M2 核心抽牌 | Python / 离线算法、会话状态机、手动选牌、快速模式、四种模式、每日唯一结果 | 无重复牌、顺序正确、结果可恢复、边界概率一致 |
| M3 查询与记录 | 全局查询、图鉴、详情、本地历史、问题、笔记、分享图 | 查询不重置会话，记录可读写删除，分享可下载 |
| M4 视觉与声音 | 复古视觉、粉金对称沙漏牌背、扑克牌式洗牌、完整 78 张网格、翻牌、音乐音效 | 手机桌面可用，音频无叠加，可关闭 |
| M5 离线与更新 | manifest、完整缓存、暂停重试、资源校验、应用更新、缓存清理 | 核心断网测试通过，不误报下载完成 |
| M6 发布验收 | Python 服务部署方案、HTTPS、PWA、错误处理与恢复、完整验收 | 第一版需求全部通过，内容 reviewed，发布资料准备完毕 |

阶段有依赖：M0 确定语义 ID 后才能开发数据与会话；PWA 可提前搭建，但资源完整性验收要等展示图和音频确定。没有已承诺的发布日期，完成时间由实施规模与验收进度决定。

## 4. 测试安排

后端使用 pytest 验证导入约束、算法边界、模式参数、幂等与查询；前端测试状态机、离线适配器、本地事务和搜索规则。两端运行共享规则样例。浏览器端到端测试重点覆盖选牌→查询→恢复→确认、每日固定、下载后断网、导出图片。

自动测试不能替代音乐、触控、牌背比例和字体的实际检查。每轮完成必要测试后，根据新增改动和失败项补测，不反复运行无关检查。

## 5. 性能与资源预算

以下为首轮目标，不是已经测得的性能：

| 项目 | 目标 / 测量方式 |
|---|---|
| 卡牌展示图 | 长边约 1000–1400 px；逐张压缩，避免文字劣化 |
| 图鉴缩略图 | 长边约 240–360 px；按实际清晰度调整 |
| 核心离线包 | 尽量控制在 35 MB 内；以 manifest 实际 bytes 为准 |
| 音频扩展包 | 尽量控制在 6 MB 内，适合循环且不过度压缩 |
| 首屏关键传输 | 不超过约 2 MB，完整离线包由用户主动下载 |
| 本地查询 | 78 张数据准备好后，过滤逻辑目标 <50 ms |
| 动画 | 中等手机以接近 60 fps 为目标，不解码 78 张原始大图 |
| 在线查询 / 会话创建 | 暖服务、正常网络下响应目标 p95 <300 ms，另计网络传输 |
| 本地记录写入 | 正常设备目标 <100 ms，失败须提示 |

目标超出时先测量字体、图片、音频和渲染开销。保留原始图，只调整生成的展示版本。不为达到体积目标裁掉牌名或破坏画面。
